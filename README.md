# 聊天站 · 搭建说明

一个 WhatsApp 风格的聊天网站。**文字 + 图片**，搜名字加好友，消息**端到端加密**。

**零成本、零注册、零后端**：

- 不需要服务器、不需要数据库、不需要买域名
- 你和朋友都**不用注册、不用手机号、不用邮箱**，打开网页起个名字就能聊
- 前端放 GitHub Pages，消息走公共 MQTT 中转（EMQX 免费公共服务器）

---

## 一、部署（10 分钟，全在网页上点）

### 1. 传到 GitHub

1. 打开 <https://github.com> → 登录 → 右上角 **+** → **New repository**
2. **Repository name** 填 `chat`，选 **Public**，点 **Create repository**
3. 点 **uploading an existing file**
4. 把本文件夹里这些**全部**拖进去：

   ```
   index.html
   styles.css
   app.js
   README.md
   vendor/          ← 这个文件夹也要，里面是 mqtt.min.js
   ```

   > `vendor` 要变成一个文件夹，里面装着 `mqtt.min.js`。
   > 如果拖上去发现是散的，就 Add file → Create new file，文件名填 `vendor/mqtt.min.js`，再把内容粘进去。
5. 拉到底点 **Commit changes**

### 2. 开 GitHub Pages

1. 仓库里点 **Settings** → 左侧 **Pages**
2. **Source** 选 **Deploy from a branch**
3. **Branch** 选 **main**，右边选 **/ (root)**，点 **Save**
4. 等 1～2 分钟刷新，顶上会出现：

   ```
   Your site is live at https://你的用户名.github.io/chat/
   ```

**这就是网址，发给朋友就行。**

> 手机建议加到桌面：浏览器菜单 → 添加到主屏幕，看起来就像个 App。
> ⚠️ **必须用 https 打开**（GitHub Pages 就是 https）。浏览器只在 https 下才给用加密功能。

**没有别的步骤了 —— 不用填任何配置。**

## 二、怎么用

1. **第一次打开**：起个名字 → 开始聊天
2. **加好友**：在上面搜索框输入对方的**完整名字** → 回车或点放大镜 → 点结果 → 开聊
   - 不用对方同意，你搜到他、点了，他就在你的列表里；他那边收到你消息时也会出现你
3. **发消息**：打字回车，或点图片按钮选图
4. **已读**：你发的消息，一个 ✓ 是发出去了，两个蓝色 ✓✓ 是对方看到了
5. **验证码**：聊天右上角那个🔒，点开有一串数字

### 自己一个人怎么试？

开**两个浏览器窗口**：一个正常窗口 + 一个无痕窗口（或用两个不同浏览器）。
各起一个名字，互相搜一下就能聊。

### 关于那串「加密验证码」

你和对方看到的数字应该**完全一样**。一样，说明中间没人在偷看。
打电话或当面念一遍对一下 —— 对不上就说明有人在中间做手脚，别在那个聊天里发重要东西。

## 三、怎么加密的

- 每个人第一次打开时会在这台设备上生成一对密钥（浏览器自带的加密功能，不外传）
- 你俩的公钥会自动交换，然后各自算出一把**只有你俩有**的密钥
- 每条消息（包括图片）都用这把密钥加密后才发出去
- 中转服务器（MQTT broker）上跑的全是密文，**它自己解不开**

## 四、必须提前知道的限制

不藏着，都写清楚：

| 事项 | 说明 |
|---|---|
| **中转服务器是公共的** | 用的是 EMQX 免费公共服务器 `broker.emqx.io`，谁都能连。**消息内容读不到**（有加密），但**「谁在什么时候发了几条、多大」这类信息是公开的**。不适合聊特别敏感的事。 |
| **不保证稳定** | 公共服务器是免费共享的，偶尔会卡、会限流、会断线。断线时左下角会提示，会自动重连。 |
| **不能发视频** | 只做了文字和图片（按你的要求）。 |
| **图片会自动压缩** | 选多大的图都会压到 340KB 以内再发，画质会有损失。图片越大发得越慢。 |
| **名字要输对** | 搜好友必须**完整名字一字不差**（空格、大小写不影响）。这是故意的 —— 不然谁都能把整站用户列表拉下来。 |
| **身份绑浏览器** | 身份存在浏览器里。换设备、清浏览器数据 = 新账号，老聊天记录也读不出来了（密钥没了）。 |
| **老消息会一直堆在服务器上** | 消息是"常驻"存在中转服务器上的（这样换设备也能看到历史）。聊得特别多会越堆越多。 |
| **对方公钥被掉包** | 理论上有人能在中间冒充。用「加密验证码」对一下就能发现。 |
| **对方不在线也收得到** | 消息发出去就存在服务器上了，他下次打开就能看到。 |

## 五、文件都是干嘛的

| 文件 | 作用 |
|---|---|
| `index.html` | 页面结构 |
| `styles.css` | 外观（WhatsApp 配色、气泡、深色模式） |
| `app.js` | 全部逻辑（加密、MQTT、图片切片、界面） |
| `vendor/mqtt.min.js` | MQTT 客户端，已经放在本地，不依赖外部 CDN |
| `README.md` | 这个文件 |

## 六、出问题了？

| 现象 | 原因 |
|---|---|
| 起名按钮点了没反应 / 提示要 https | 你是用 `file://` 双击打开的。必须通过网址访问（GitHub Pages 或本地起个服务器） |
| 左下角一直显示"连接断开" | 网络问题，或者公共服务器在抽风。等一会儿会自动重连；不行就刷新 |
| 搜不到好友 | 名字没输对（要一字不差）；或者对方还没打开过这个网站 |
| 发消息提示"还没拿到对方的公钥" | 让对方先给你发一条消息，你就能回了 |
| 图片显示"图片打不开" | 网络抖动导致分片没传全。刷新一下页面会自动补上 |
| 消息顺序乱 | 刷新一下页面 |
| 想彻底重来 | 点右上角 👤 → 最下面"清空身份，重新开始" |
